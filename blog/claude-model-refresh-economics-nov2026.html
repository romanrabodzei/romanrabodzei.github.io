Claude's November Model Lineup: Opus 5.5, Haiku 5.5, and the Economics of "Good Enough"

Roman Rabodzei · Nov 2026 · ~6 min read
Claude AI Agents Model Selection FinOps Microsoft Foundry

Within about three weeks of each other, Anthropic shipped Claude Sonnet 5.5, Claude Haiku 5.5, and Claude Opus 5.5 — a full-tier refresh rather than a single flagship update. The headline number worth sitting with: Opus 5.5 costs roughly 40% less to run than Opus 5 for typical workloads while leading in agentic coding and knowledge work. If you built a model-routing policy around last generation's pricing, it's already stale.

What changed, tier by tier

// Opus 5.5

Still the frontier tier, still the one to reserve for genuinely hard reasoning — but the 40% cost reduction versus Opus 5 at comparable workloads changes the calculus on what counts as "worth it." Subtasks that got routed to Sonnet purely on cost grounds last quarter may now be cheap enough to send to Opus directly, if the quality difference was ever the limiting factor.

// Sonnet 5.5

Positioned as the clear mid-tier upgrade: 30%+ faster than Sonnet 5, and up to 30% cheaper for most work. This is the tier most production agent subtasks should default to, and the faster+cheaper combination (rather than a trade-off between the two) is the more unusual part — normally a speed gain costs something.

// Haiku 5.5

Explicitly built for high-volume work — summarization, subagents, and browser use — which is a more specific positioning than "the cheap one." If your agent architecture has a fan-out pattern (one orchestrator spawning many short-lived subagent calls), Haiku 5.5 is squarely aimed at that fan-out layer rather than being a fallback for when Sonnet is too expensive.

Why "re-benchmark every refresh" still holds

The model-routing discipline from earlier this year still applies, unchanged: baseline quality on the most capable model, test cheaper tiers against that baseline on real production examples, and route to the cheapest tier that clears your quality threshold per subtask. What's different this time is that the cost floor moved at every tier simultaneously, not just at the bottom — which means a routing policy tuned for the previous generation's pricing is now leaving savings on the table across the board, not just missing out on a new cheap option.

Worth doing this month: re-run your existing subtask-quality benchmarks against the 5.5 lineup before assuming your current routing table is still optimal. A 30-40% cost shift at every tier is large enough to change which tier clears your quality bar at the lowest price, even if your thresholds haven't changed at all.

Availability

All three are available through the same channels as the prior generation — Anthropic's API directly, and via Microsoft Foundry and GitHub Copilot's model picker for teams already standardized on those platforms, so swapping model IDs in an existing routing config is typically the entire migration effort.
