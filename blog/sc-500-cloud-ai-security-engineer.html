SC-500: Microsoft Certified Cloud and AI Security Engineer Associate

Roman Rabodzei · Sep 2026 · ~8 min read
Certifications SC-500 Azure Security AI Security Microsoft Learn

I passed SC-500 — Microsoft Certified: Cloud and AI Security Engineer Associate — this month. It's a timely one to write about: Microsoft retired Azure Security Engineer Associate (AZ-500) on August 31, 2026 — the certification, exam, and renewal assessments all stopped being available on that date. SC-500 is its direct successor, and the shift in name is the shift in scope: from securing Azure infrastructure to securing Azure, hybrid, and AI-enabled environments. Here's what it actually covers and what I found useful in practice.

What SC-500 is and why it exists

Per Microsoft's own certification page, SC-500 validates your ability to "design, implement, and manage end-to-end security controls across Azure, hybrid, and AI-enabled environments to protect identities, data, applications, infrastructure, and maintain regulatory compliance." That's a direct expansion of the AZ-500 scope — the same core responsibilities (identity, network, compute, storage, posture management) plus an explicit, recurring responsibility to secure AI solutions and ensure the platforms, data, identities, and infrastructure used by AI workloads are securely implemented and monitored.

This isn't a bolted-on AI module. AI security shows up as a thread running through the existing security domains rather than as its own separate domain — you're not tested on "AI security" in isolation, you're tested on identity, network, compute, and posture management questions where the workload in the scenario happens to be an AI service, an agent, or a model deployment.

What the exam actually covers

Microsoft publishes four assessed domains for SC-500. This is the real, current breakdown, not a reinterpretation:

// Manage identity, access, and governance

Securing access with Microsoft Entra ID and Azure Key Vault, and enforcing security and regulatory compliance. This is classic identity and governance territory, carried over almost directly from AZ-500 — conditional access, privileged identity management, RBAC, policy, and compliance controls. The AI angle here is about identity for AI workloads specifically: managed identity for AI service authentication, least-privilege access to model deployments, and role assignments for Microsoft Foundry.

// Secure storage, databases, and networking

Network isolation, private endpoints, storage and database security — again a direct extension of AZ-500 content. Where AI enters: securing the data stores behind AI solutions (vector search indexes, Cosmos DB with vector indexing, Azure AI Search), ensuring training and inference data doesn't leak across tenant or network boundaries, and customer-managed keys for AI-related storage.

// Secure compute

Traditional compute security (VMs, containers, AKS) plus securing the compute layer that AI workloads run on — Azure OpenAI and Foundry deployments, content filtering configuration (Azure AI Content Safety), input/output filter policies, and hardening system prompts and RAG grounding as a trust boundary against prompt injection.

// Manage and monitor security posture

Posture management with Microsoft Defender for Cloud and Microsoft Sentinel, extended to cover AI-specific signals: Defender for Cloud's AI security posture management features, and monitoring for anomalous prompt patterns, unusual token consumption, and content policy violations as part of the broader security monitoring story.

What actually changed from AZ-500: the domain names and core skills (identity, network/storage, compute, posture) are the same shape as AZ-500. What's new is that every domain now explicitly includes securing the AI layer — AI service identity, AI data stores, AI compute (Foundry, Azure OpenAI), and AI-aware posture monitoring — woven into the existing structure rather than added as a fifth domain.

Why I took it

After AI-103 and AI-200, I'd been building AI solutions from the developer's perspective — agents, Foundry, orchestration, cost optimisation. SC-500 gave me the structured vocabulary for the security conversations those projects require. When someone asks "how do we prevent users from extracting sensitive data through the model?" or "what does our audit trail look like for AI-generated content?", having passed SC-500 means I've thought through those questions systematically, not just ad hoc.

It's also a certification that doesn't have a large community of write-ups yet — it's the direct AZ-500 successor and only recently became the exam people are pointed to. Being early to a certification with this much overlap in real project work means the content is fresher and more directly useful than an older cert where the study material has been ground into question banks.

How I prepped

The official study guide is the starting point — aka.ms/SC500-StudyGuide. Because SC-500 carries over most of AZ-500's skill areas, existing AZ-500 study material (Defender for Cloud, Sentinel, Entra ID, network security) is still directly useful — you're not starting from zero even if you've never touched an AI service. The genuinely new ground is where each domain extends into AI: Foundry, Azure OpenAI, and AI Content Safety configuration.

  • Read the four assessed domains on the official certification page closely — identity/access/governance, storage/database/networking, compute, and posture management — and map your existing Azure security knowledge onto each before touching AI-specific material.
  • Get hands-on with Azure AI Content Safety and Azure OpenAI network and identity configuration. The portal flows matter — the exam includes scenario-based questions where you need to know which blade, which setting.
  • Review Defender for Cloud's AI security posture management features — these are new enough that most AZ-500 prep material doesn't cover them, but they show up explicitly in the current study guide.
  • Work through the OWASP LLM Top 10 as background reading for the prompt injection and content-safety questions, even though it isn't an official Microsoft resource — it maps well onto the compute-security domain's AI content.
  • The exam is 120 minutes, proctored, with a mix of multiple choice and scenario-based questions. Budget time for the longer scenario sets.

Practical takeaways

If you hold AZ-500 already, it stays on your transcript, but it can no longer be renewed or re-earned after August 31, 2026 — SC-500 is what a hiring manager or your own transcript will expect to see going forward. If you're starting from scratch, SC-500 is now the correct entry point rather than a certification to take after AZ-500.

The exam domains translate directly into questions any security-conscious team should already be asking as AI workloads land in production: who has access to the model deployment, is the data store behind the AI solution isolated correctly, is the compute layer running Content Safety and input filtering, and does the security posture monitoring pick up anomalous AI usage the same way it picks up anomalous infrastructure activity. SC-500 gives that a structured, testable shape instead of leaving it to ad hoc review.

If you're working on AI solutions on Azure — building agents, deploying LLMs, integrating Azure AI services — SC-500 provides the security framework that should be layered on top of that work. It's not a compliance checkbox. It's a structured way to think through a genuinely new attack surface that most cloud security practitioners haven't had to reason about before.
